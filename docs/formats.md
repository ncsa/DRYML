# V1.1 Formats

The v1.1 metadata contract uses closed canonical JSON envelopes. Every emitted envelope has exactly `contract_version`, `schema`, `kind`, `payload`, `id`, and optional `metadata`; `contract_version` is exactly `"1.1"`. Parsers reject missing or unknown fields, source-v1 and future versions, duplicate textual JSON keys, invalid UTF-8, non-finite values, invalid bounds, and attached IDs that do not validate.

Canonical JSON has sorted string keys, compact UTF-8 encoding, finite floats, and detached deeply immutable projections. Defaults are depth 8, 1,024 nodes, 64 entries/container, 4,096-codepoint strings/keys, 4,096-bit integers, and 4,194,304-byte envelopes. Environment records allow 4,096 distributions, 65,536 nodes, and 16,777,216-byte envelopes. Public diagnostics are redacted and bounded to 512 codepoints with at most 64 entries per report.

IDs are `<prefix>-v1.1-<64 lowercase hex>` SHA-256 hashes over a domain-separated canonical preimage containing the prefix, version, schema, kind, and identifying payload. Envelope metadata never changes an ID. Record paths/prefixes, distribution installation facts, DRYML git revision, and `details` are non-identifying; requirement `details` are non-identifying.

Environment records contain closed Python, platform, distribution, and optional DRYML records. The `current`, `python`, `conda`, and `container` spec kinds preserve their exact tagged fields; a Conda spec requires exactly one of `prefix` or `name`. World-family values and embedded session allocations allow 4,096 roles, 4,096 total processes, 256 entries per resource map, 65,536 nodes, and 16,777,216-byte envelopes. Count constraints use explicit nullable non-negative `min`/`max`. Requested processes contain resources, optional environment/runtime IDs, string environment overrides, and metadata. Exact process allocations additionally bind role-local replica/rank fields, CPU and accelerator identities, per-device memory, and named resources. Runtime allocation associations are nullable `worldalloc-v1.1-*` IDs, never CDef references.

Typed public snapshots and DRYML-authored session/runtime diagnostics retain process-environment keys but replace values with `"<redacted>"`. Credential-like keys and recognizable supplied secrets are replaced before formatting. URI projections remove user information, query, and fragment; absolute POSIX, drive-qualified Windows, UNC, and home-expanded paths become `"<local-path>"` unless documented as public artifact paths. Redaction precedes the 512-codepoint and 64-diagnostic bounds. `file:` URI masking, exhaustive third-party exception/log redaction, and protection of weak secrets embedded in semantic IDs are deferred.

No v1.1 family stores CDef references, Store authority, Object state, records/provenance sidecars, or query-index data. All ten families use the table above and reject source-v1 artifacts rather than translating or migrating them.
